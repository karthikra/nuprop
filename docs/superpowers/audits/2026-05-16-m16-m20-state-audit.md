# M16–M20 State Audit

**Date:** 2026-05-16
**Author:** Audit run during session that opened with HANDOFF.md claiming M16-M20 unstarted.
**Conclusion:** Handoff was wrong. M16-M20 are substantially scaffolded at the backend, with critical security/observability holes, sparse frontend, and minimal pipeline integration.

This document is the canonical truth baseline. Future sessions read this before the slice-by-slice plans in `docs/superpowers/plans/`.

## TL;DR

The work is **~60% done, 40% remaining**, where the 40% is the hardest 40%:

- **Backend**: scaffolded with 5 CRITICAL + 13 HIGH issues. Encryption silently falls back to plaintext if `ENCRYPTION_KEY` is empty. OAuth `state` is never validated (CSRF wide open). Bare `except: pass` swallows every error. No logging module imported anywhere in M16-M20 backend.
- **Frontend**: Drive/Calendar/Slack have **no React Query hooks**, **no Slack OAuth callback route**, **zero tests** for any M16-M20 component, and no UI to add manual context after a client is created.
- **Pipeline**: Of 7 phases, **only `run_research` consumes M16-M20 data**. `build_cost_model` ignores `proposal.preferences` entirely. `run_ideation` has zero client context. EmailIndex is populated but never automatically merged into `context_profile` post-sync.
- **Production**: Fly has 6 secrets. Missing: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `ENCRYPTION_KEY`. **No Google Cloud or Slack OAuth app registered.**

Total realistic shipping work: **5–8 dev-days + ~1hr of OAuth-console clicking by the user.**

## CRITICAL findings (must fix before any user touches connectors)

### Backend

1. **`connector_viewmodel.py:53-65` — encryption silent fallback to plaintext.** `_encrypt()` returns the input unchanged if `get_settings().ENCRYPTION_KEY` is empty, with no log warning. Production deploys where the secret is missing will store Google refresh tokens unencrypted in Postgres. **Fix:** fail-loud at startup if `ENCRYPTION_KEY` is unset *and* any connector code is enabled; never silently plaintext.

2. **`connector_viewmodel.py:194-214` — bulk email insert relies on session-end commit.** Emails are `db.add()`'d in a loop but never explicitly committed inside the loop. Any exception after the loop (logging, broadcast, etc.) triggers `get_db()`'s rollback path and the entire sync batch is lost. **Fix:** commit per N records, or per-domain; record sync checkpoint so retry resumes.

3. **`gmail_client.py:78-79, 127-128, 159-160` + `connector_viewmodel.py:219, 306, 358, 470` — `except Exception: pass`** on revoke, OAuth response parsing, message fetch, and per-client sync loops. No retry, no backoff, no logging. **Fix:** narrow the except, log with `logger.exception`, decide per-call whether to retry vs surface to the caller.

4. **`connector_viewmodel.py:60-65` — `_decrypt()` doesn't catch `InvalidToken`.** Rotating `ENCRYPTION_KEY` between deploys instantly bricks every stored token because decryption raises and crashes the request. **Fix:** catch `InvalidToken`, log, force re-auth flow.

5. **`gmail_client.py:42-52, 54-63` — OAuth response unvalidated.** `tokens["access_token"]` assumes Google returned a success; an error response (`{"error": "invalid_grant"}`) raises `KeyError`. **Fix:** check for `error` field, return structured failure.

### OAuth state / CSRF (HIGH but related to the CRITICAL set)

6. **`connector_viewmodel.py:69-99` — `state` parameter never validated.** Set to `str(agency_id)` on auth-url, never checked on callback. CSRF wide open — an attacker can replay an old code or trick a user into authorizing the attacker's agency. **Fix:** sign state with HMAC of agency_id + nonce + expiry; verify on callback.

### Architectural — affects everything else we ship

7. **No `logging` module imported in M16-M20 backend.** Every `except` is silent. **Fix:** add a module-level logger to every M16-M20 file; bare `pass` becomes `logger.exception(...)`.

8. **Services instantiated inside route handlers.** `clients.py:95, 127, 432` does `svc = ContextService()` inline. Breaks MVVM and FastAPI DI. **Fix:** add to `core/deps.py`, inject via `Depends`.

### Frontend

9. **Slack OAuth callback has no route.** Backend has `POST /connectors/slack/callback`. Frontend opens a Slack popup with no `/settings/slack-callback` page to handle the redirect. The OAuth flow can never complete. **Fix:** add `slack-callback.tsx` modeled on `gmail-callback.tsx`, route it in `App.tsx`.

10. **Drive / Calendar / Slack have no React Query hooks.** `agency.tsx` uses raw `api.post()` with silent `.catch(() => {})`. No types, no loading state, no error feedback. **Fix:** mirror the Gmail hook pattern in `frontend/src/api/connectors.ts` for all three.

11. **Zero vitest tests for M16-M20 surface.** Not a bug per se but a CRITICAL gap for a surface this large. **Fix:** add tests as part of every UI slice.

## HIGH severity (will bite production users within a week)

### Backend

- **`gmail_client.py:151-163` — pagination loop can infinite-loop** if Google returns 0 results with a non-null `pageToken`.
- **`connector_viewmodel.py:208` — `to_addresses=msg.get("to", "").split(",")`** produces `[""]` when `to` is empty. Corrupts the JSON column.
- **`gmail_client.py:127-128` — malformed email date defaults to `datetime.now()`.** Original timestamp lost; time-based sorting becomes wrong.
- **`connector_viewmodel.py:248` — `email.split("@")[-1]` without `@` validation.** Crashes on `"user"` or `"@domain"`.
- **No retry/backoff for any external API call** (Gmail, Drive, Calendar, Slack, Bedrock). 429s and 500s fail the whole sync.
- **No timeout on LLM calls** in `context_service.py`.
- **Redirect URIs hardcoded to `localhost:5173`** in `config.py:78, 83`.
- **`client_repo.search(agency_id, limit=500)`** — agencies with >500 clients silently miss the tail.

### Frontend

- **No context-input UI on Client Detail page** — manual context can only be entered via the proposal builder's `ContextCheck`, only on new proposals without history.
- **No context-brief preview** — users can't see what the AI sees about a client.
- **No error state UI** for any sync — silent `.catch()` everywhere in `agency.tsx`.
- **No disconnect button for Drive / Calendar** — only Gmail has one.
- **No sync status / last-sync time for Drive / Calendar** — only "Sync Now" button shown.

### Pipeline

- **`build_cost_model` ignores `proposal.preferences`** (gap #3 in pipeline audit). `generate_preference_overrides` writes `pricing_model=tiered` and `negotiation_buffer=12` to `proposal.preferences`, but `CostModelBuilder.build()` is called with only `template_config` (`pipeline_service.py:351-357`). The whole intelligence-layer-feeds-pricing loop is broken.
- **`run_ideation` has no client context.** The ideation side-channel can't see relationship status, past rejections, or pricing sensitivity (`ideation_service.py:77-119`).
- **`enrich_context_with_emails` is on-demand only.** Gmail sync writes `EmailIndex` rows; nothing automatically merges them into `context_profile`. The only way email intel reaches a proposal is to manually hit `GET /clients/{id}/context-brief?include_emails=true` before generation.
