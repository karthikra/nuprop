## Decisions that shaped S9 (so you don't re-litigate)

The previous session "grilled" the user through 14 design forks before writing the mega-spec. Key locked decisions for S10+ to honor:

- **Schema is per-column.** One JSON column per section type, NOT a single `sections: list[Section]`. Order is canonical, hardcoded in `app/services/sections/__init__.py::SECTION_ORDER`. Don't reintroduce a list shape.
- **Two-pass generation** (7 facts parallel + 2 synthesis sequential) was deliberately chosen over single-call structured output. Per-section regenerate is the headline UX.
- **Editor is long-form scrollable**, not per-section chat-card. User explicitly chose this over the "stage per section" pattern that fits the existing chat-card precedent.
- **Media uniformly via fal.ai** (Nano Banana for image, Kling 1.6 for video, TTS for narration). Single vendor relationship, single API key, single service-module shape per kind.
- **All media types in every section** — uniform schema; user decides what makes sense per proposal.
- **Section types: exactly 9.** No CTA, no Appendices. User was explicit.
- **NUSTAGE pulls** via `GET /export?token=<share_token>`. Not a push model. NUSTAGE doesn't need to know NUPROP exists at integration time.
- **Auto-save per-section** (1s debounce) + explicit Publish. No "Save proposal" button.

## Conventions to maintain

- **Git commits:** no AI/Claude attribution, no `Co-Authored-By:` line. Conventional-commit prefix (`feat`, `fix`, `refactor`, `docs`, `test`, `spec`, `plan`, `ci`).
- **Staging:** explicit paths only — never `git add -A` or `git add .`. There was an incident in S5 with a `backend/.venv` symlink getting committed; the per-path discipline came from that.
- **Worktrees:** use `EnterWorktree` for per-slice isolation. The native tool is preferred over manual `git worktree add`.
- **Subagent-driven execution:** fresh subagent per task + two-stage review (spec compliance then code quality). Don't skip reviews even on small tasks.
- **Date format in docs:** ISO `YYYY-MM-DD`. Specs and plans live at `docs/superpowers/{specs,plans}/YYYY-MM-DD-<name>.md`.
